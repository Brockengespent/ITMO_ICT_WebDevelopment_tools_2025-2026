ЛР1

FastAPI сервер для управления задачами

В первой работе реализовано серверное приложение Time Manager API с аутентификацией JWT, ORM на SQLAlchemy, миграциями Alembic и PostgreSQL как основной базой данных.

  • Роутеры для пользователей, категорий, тегов, задач и времени
  • Авторизация и хэширование паролей
  • Подготовленная структура для расширения API

ЛР2

Параллелизм: потоки, процессы и async

Во второй работе сравниваются подходы threading, multiprocessing и asyncio на CPU-bound и I/O-bound задачах: вычисление суммы и параллельный парсинг страниц с сохранением в БД.

  • Сравнение производительности подходов
  • Использование aiohttp, requests и BeautifulSoup
  • Запись результатов в PostgreSQL

ЛР3

Docker, парсер и Celery-очередь

Третья работа объединяет API из ЛР1, парсер-сервис, Redis и Celery. Приложение упаковано в Docker и запускается через docker-compose как набор связанных сервисов.

  • Отдельный контейнер для API и парсера
  • Очередь задач через Celery + Redis
  • HTTP-вызов парсера и фоновые задачи

Как связаны лабораторные

ЛР1

Создает основу проекта: API, модели данных, миграции, JWT-аутентификацию и структуру, с которой дальше работают остальные работы.

ЛР2

Показывает, как выбирать правильный способ параллелизма для разных типов задач и как сохранять результаты парсинга в ту же БД, что и в первой работе.

ЛР3

Упаковывает все в инфраструктуру: контейнеры, очередь задач и отдельный парсер-сервис, который использует наработки из предыдущих лабораторных.

Итоговая логика такая: ЛР1 дает сервер и БД, ЛР2 — инструменты параллельной обработки и парсинга, ЛР3 — разворачивает это как распределенную систему.
